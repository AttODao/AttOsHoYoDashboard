# R2 — AGD / NFT-Web3 mood

## 確定した入力

ユーザーの追加指示を優先する。旧A/Bの選定は保留し、[指定の参照UI](https://www.uupm.cc/demo/nft-web3)の雰囲気、AGD表記、サイドバー廃止、設定の集約、共通ユーザー名、仮登録フローの隔離を今回の基準にする。AI案の最終的な視覚編集・承認は人間が行う。本番Dioxusは実装しない。ユーザーがMCP利用を再開可能と知らせるまでPenpot操作を行わない。

参照サイトを公開HTTPとローカルChromiumで実際に確認した。1440／390pxで描画し、黒いナビ、暗いカード、8pxのボタン角丸、マゼンタ→シアンのCTA、Orbitron見出しとExo 2本文を確認。AGDでは日本語本文をNoto Sans JP、ブランド／主要数値をOrbitronにする。参照のNFT画像、ウォレット、取引実績、広告的コピーを製品へ流用しない。装飾用の3D画像や公式ゲーム素材は追加しない。

## 情報設計

| 画面 | 含む責務 | ナビゲーション |
|---|---|---|
| ログイン | 共通ユーザー名、ログイン方式、パスワードまたはパスキー | 通常ログイン→ダッシュボード、仮登録→初期設定 |
| 初期設定 | パスワード変更、Cookie保存、本人確認と失敗／待機 | 完了前はログアウトのみ。本人確認成功後にダッシュボード |
| ダッシュボード | ゲーム選択、表示ONかつ検出済みUID、リソース・派遣、原神／スターレイルの自動受取ON/OFF | 上部メニュー1か所。時刻入力・手動実行・履歴を置かない |
| 設定 | UID表示、報酬時刻／手動実行／5日履歴、同じHoYoLAB UIDのCookie更新、パスワード・パスキー、自己削除 | 同じページ内のセクション移動。ダッシュボードへの戻り |
| 管理者設定 | ユーザー作成・無効化／再有効化・復旧用パスワード・削除、ログ確認の置き場所 | 管理者だけがメニューからアクセス。一般ユーザーには表示しない |

Desktop／Mobileとも、アプリ上部にメニューボタンを1つ置く。項目はHoYoLAB連携、設定、管理者設定、ログアウト。HoYoLAB連携は設定内の連携セクションへ移動する。設定の目次はページ内の操作であり、常設サイドバーではない。

DashboardはDesktopで約1232pxの幅を使い、ゲーム状態を大きく、ボーナスON/OFFを右側にまとめる。Mobileはゲーム状態→自動受け取りの1カラム。ボーナスを画面下に埋もれさせない最終順序・密度は人間の調整対象。ON/OFFはアカウント×ゲームであり、UID選択から独立する。OFFのカードは「設定時刻」と表示し、次回の実行が予約済みとは偽らない。

## 状態・安全性

- 初期設定の進行条件はパスワード変更完了＋Cookieの本人確認成功。Cookie保存を完了扱いしない。ログイン済み利用者の通常設定とは別画面にする。
- 初期設定中はメニュー、設定、管理者画面、クリック可能なロゴを出さない。戻る／URLを変えても未完了なら初期設定に留まる表示例を作る。これはプレビューの導線検査で、サーバー認可の代替ではない。
- 新UIDは非表示のまま。完了後のDashboardがEmptyでも、勝手に表示ONへ変更しない。設定のゲーム表示で選ぶ。
- パスワード・パスキーのユーザー名は同じ入力欄。実装時はパスワードマネージャ・貼り付けを妨げない。プレビューの読取専用は秘密の入力を防ぐためであり、本番フォームの仕様ではない。
- LoadingをEmptyと区別する。古いデータには取得日時、失敗には別のエラー時刻を表示する。パスキー中断、設定不足、ログアウト不明の状態を用意する。
- 202は受付のみ。`unknown`の原神実行は再送ボタンを無効化する。自己削除の受付と背景削除完了を区別する。管理者による他人の削除では管理者自身のセッションを維持する。
- 自動受け取りは初期OFF、06:00、固定+09:00。時刻変更は次の未来の実行から適用する。Cookie更新は同じHoYoLAB UIDのみ。
- 復旧は対象のセッション・パスキーを失効。再有効化で旧セッションを復活させず、自動受け取りOFFを維持する。公開登録、ロール編集、メール復旧、別UIDへの連携変更、他人のゲーム情報閲覧を追加しない。

## 管理者のログ確認：未確定部分

ユーザーの追加要望として場所を確保するが、現行OpenAPIに管理者用ログ一覧はない。本人の報酬履歴やサーバーのtracing出力を、管理者向けの監査ログAPIとして流用しない。UIは「仕様確認が必要」を明示し、ロード操作を無効化する。これはHoYoLAB機能の古い利用制限の復活ではない。

再開時に決めること：管理操作の監査ログ、報酬ワーカーの運用ログ、サーバー診断ログのどれを見るか。対象項目、閲覧権限、保存期間、ページング、秘密・個人情報の除外も必要。パスワード、Cookie、パスキー応答、上流の生エラーを表示／保存しない。現段階ではAPI・DB・権限モデルを新設しない。

## 本番責務との対応

`pages/dashboard.rs`はデータ表示、`pages/rewards.rs`は報酬設定／実行／履歴、`pages/accounts.rs`はUID表示、`pages/hoyolab.rs`は連携、`pages/security.rs`は認証設定、`pages/deletion.rs`は自己削除、`pages/admin.rs`はユーザー管理、`pages/auth.rs`と`app/state.rs`はログイン・初期設定の責務を維持する。設定ページへの集約は既存の表示責務をまとめる案であり、全ロジックを1ファイルに詰める指示ではない。API契約とbusiness-layerの認可条件は変更しない。

## オフライン取り込み準備

`preview/scene.mjs`はこの合成プレビュー専用。任意サイトからの取込器ではない。実書体のCSS矩形・色・テキストと少数pathアイコンを計測し、確認用フッターを除く。入力の`.value`や非radioの`value`属性は読まず、ユーザー名・Cookieの注意文・空パスワード・初期06:00を合成する。ブラウザ検査では値getterを失敗させても計測が完了することを確認する。通常場面とモーダルのviewport切り出しは別に扱う。

`preview/check.mjs`がDesktop／Mobile各25場面を生成する。基本7画面状態、Loading／Empty／Error／設定不足／権限不足／パスキー中断、管理者の再発行／削除ダイアログ、初期設定のCookie入力／本人確認待ち／新UID非表示、パスキー方式、一般／管理者メニュー、ON切替、スターレイル、自己／管理者削除受付を含む。HTML／CSS／JS／計測コードのSHA-256を添え、以前のモデルとの取り違えを防ぐ参照値にする。

`penpot/r2-import.js`は再開許可後に**50場面の実取り込みに成功**。現在の保存状態・停止理由は[`native-status.md`](native-status.md)。生成JSONを`storage.agdR2Scene`へセットして1場面ずつ実行する。対象ファイルID、既存キー、書体、配色、寸法を先に検査し、既存R1・人間の編集を上書きしない。中断マーカーが残った場合は止まり、状態確認なしの再実行を拒否する。セッションstorageを失った既存R2にも自動再生成しない。

準備している出力はネイティブBoard／Text／小さなベクトル、共通Button／Input／SwitchのAssetsとコピー、色・文字サイズ・角丸・Button内paddingのtokens、書体のTypography assets。グラデーションは確認済みのNative Gradient APIを使用する。SVG経由の変換は失敗したため廃止し、画像へのfallbackはしない。書体ファミリーはTypography assets、グラデーションは部品masterで編集する想定。色Assetsの値を変えるだけでtokensが同期するとは保証しない。

**残る制約**：主要Native APIと10場面のexportは実確認したが、全場面のAPI互換性、path編集性、字体と文字コピーの描画キャッシュ、共有編集、token反映の最終検査は未完了。masterのfill反映は実確認したが、token／TypographyのSDK値変更だけでの既存図形の自動同期は確認できていない。単一テキストButton以外の複雑な配置は計測位置を保持し、柔軟なAuto Layoutは初回Native確認後に整える。背景のradial ambient、CSS shadow、hover／focusはこの計測器では移植しない。action metadataから`r2-finish.js`で代表導線を作成し、全50場面へ代表導線240件と両viewportのLogin／Setup／Daily／Admin開始Flowを実作成した。フォーム入力や全状態組合せのシミュレーションではない。Design System説明ボードは`AGD R2 Draft / Guide`に追加・画像確認済み。これらを省いたままR2完成・最終合格とは扱わない。コピー文字はmetadataとglyphが食い違う場合があるため、`r2-refresh.js`の2RPC更新と実exportで確認する。

## MCP再開後の作業

1. 正常になった接続を使い、ファイルと保存状態を読み取り確認する。接続設定の再修復を前提にしない。
2. 旧`Draft / ...`と空の`Page 1`を残す。準備コードの対象は`AGD R2 Draft / Desktop`、`AGD R2 Draft / Mobile`、`AGD R2 Draft / Components`。Loginと主要10場面の確認は実施済み。保存キーと中断マーカーを照合して不足分のみ進める。Design Systemの説明ボードも追加済み。人間が編集した既存ボードは上書きしない。
3. このプレビューを配置の参照にしつつ、ネイティブテキスト、Button、Field、Switch、Notice、GameStatus、Menuなどを部品化する。HTMLやPNGを1枚貼って完了にしない。
4. R2の色・余白・角丸・文字サイズ・書体を新しいAssetsへ登録。共有変更、コピー文字の描画、長い日本語の折り返し、初期設定の遷移禁止、Mobileメニューを実際に検査する。
5. 初期設定・通常利用・管理者のプロトタイプフローを分けてリンクする。未実装のログは操作可能なAPIとしてリンクしない。人間の選定後にのみRSX実装へ進む。
